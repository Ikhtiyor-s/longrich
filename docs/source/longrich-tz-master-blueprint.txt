02. PERSONALAR, ROLLAR VA RUXSAT
Guest: browse, search, guest cart. Customer: addresses, checkout, orders, returns, reviews. Seller Owner: organization, members, catalog, finance. Seller Manager: products, order and inventory. Seller Operator: pick/dispatch limited. Warehouse Manager/Receiving/QC/Picker/Packer/Dispatcher/Inventory Auditor: WMS role-bound work. Courier: assigned shipments only. Support Agent: tickets and scoped order context. Moderator: seller/catalog approvals. Finance Manager: ledger, reconciliation, payouts under maker-checker. Super Admin: global policy operations, but no plaintext secrets; System Auditor: immutable audit read-only.
Auth: SMS OTP, normalized phone, hashed OTP, TTL, per-phone/device/IP rate limits, session rotation, refresh revoke, admin MFA. RBAC + resource ownership + seller_id isolation; never rely on UI hiding for authorization. Admin impersonation if ever needed must be time-bound, opt-in, auditable and prohibited for finance.


03. SYSTEM ARCHITECTURE / ADR-001
Chosen: modular monolith (NestJS TypeScript) + transactional outbox + worker jobs. Next.js/TypeScript: buyer, seller, admin, warehouse web; Flutter: buyer Android/iOS. PostgreSQL primary transactional store; Prisma migrations; Redis caching/locks/BullMQ; OpenSearch for search; S3/MinIO object storage; reverse proxy HTTPS; OpenTelemetry + Prometheus/Grafana/Loki; GitHub Actions CI. Docker Compose for development; production isolated services, backups and restore validation. Migrate to microservices only with measured need.
Module boundaries: identity, sellers, catalog, offers, pricing, inventory, cart, checkout, orders, payments, finance, logistics, fulfillment, returns, support, seo-cms, notifications, admin-audit. Cross-module writes via application interfaces and domain services. Outbox event names versioned (payment.succeeded.v1, inventory.reserved.v1, order.created.v1, shipment.delivered.v1, refund.completed.v1). Consumers idempotent with inbox/dedup table.
Single source of truth for each entity. Search index and inventory availability are derived projections. All external integration credentials use secret references rather than plaintext fields. No distributed ACID assumption; use compensating workflows and reconciliation.


04. CROSS-CUTTING STANDARDS
UUID identifiers; timestamps UTC; UI localizes timezone. Monetary values BIGINT minor units (UZS: 1 so‘m = 100 tiyin), rates basis points, rounding explicitly specified at item level; quantity NUMERIC with supported unit precision. Validate DB NOT NULL, unique, CHECK and foreign keys. Use immutable snapshots for order item price/title/tax/discount. Search cursor pagination; list filters/sorts whitelisted. JSON envelope {data,meta:{request_id}}; error {error:{code,message,details},request_id}; callbacks MUST use provider-native format. State transitions explicit and protected by optimistic concurrency or transaction locks. POST write operations requiring dedupe take Idempotency-Key.
Codes: 401 unauthenticated, 403 forbidden, 404 not found, 409 conflict, 422 invalid business rule, 429 throttled, 503 unavailable. Sensitive files signed URLs; malware scan; PII masking; retention periods defined separately. Definition of Done: API+DB migrations+RBAC+unit/integration/E2E+OpenAPI+docs+audit+observability, no P0/P1 open blockers.

17. KEY END-TO-END FLOWS
FLOW-A SELLER: applicant→KYB docs→moderation→contract→ACTIVE→offer→moderate→stock→visible. Exceptions: NEEDS_CHANGES, expired docs, suspended.
FLOW-B PURCHASE: browse→cart→quote→reserve→order/master/suborder→provider payment→verified success→ledger→seller/WMS fulfill→ship→proof→complete. Exceptions: quote expiry, stock race, payment timeout, late success, partial cancel.
FLOW-C REFUND: customer return request→review→return shipment if required→QC→amount computed→provider refund/manual process→verified refund→compensating ledger→closure. Exceptions: partial return, provider fail, seller dispute.
FLOW-D FULFILLMENT: inbound appointment→physical count→QC→putaway→stock availability→pick→pack→dispatch→deliver. Exceptions: shortage, damage, expiry, lost parcel.
Critical implementation principle: all status transitions have guard conditions, actor permission, idempotency and explicit rejected transitions. Write BPMN 2.0 artifacts for four flows as a separate deliverable from this textual specification.

19. API / SECURITY CONTRACT
API root /v1. Public routes separate from seller and admin. JWT/session model with logout/revoke, authorization per object. OpenAPI generated from DTOs and contract-tested. Standard pagination/filter/order documented. Request headers: Authorization, Idempotency-Key for relevant POSTs, X-Request-ID optional (server generated). Error codes STALE_QUOTE, INSUFFICIENT_STOCK, FORBIDDEN_SELLER, INVALID_STATE_TRANSITION, PAYMENT_MISMATCH, DUPLICATE_REQUEST, UNSUPPORTED_REFUND, DELIVERY_ZONE_UNAVAILABLE.
Webhooks: separate ingress, provider-native response, strict authentication/signatures, replay defense, raw payload validation, observed timestamps and dedup. Retry failed event processing via queue; poison messages to dead-letter queue and admin alert. Avoid exposing internal worker URLs publicly.
AuthZ test matrix: Seller A cannot GET/PATCH Seller B offers/inventory/orders/payables; customer cannot access another customer's address/order; warehouse worker cannot change finance; support cannot access internal secret; moderator cannot approve payout. PII/token/card data redaction in audit and telemetry.

29. TO‘LIQ TZ: STATE TRANSITIONS
Seller DRAFT→SUBMITTED→UNDER_REVIEW→APPROVED→ACTIVE; alternatives NEEDS_CHANGES/REJECTED/SUSPENDED. Product DRAFT→PENDING_REVIEW→PUBLISHED; alternatives CHANGES_REQUESTED/REJECTED/SUSPENDED/ARCHIVED. Offer DRAFT→PENDING_REVIEW→ACTIVE, may be INACTIVE/SUSPENDED. Inventory reservation ACTIVE→COMMITTED/RELEASED/EXPIRED terminal and idempotent. Checkout quote CREATED→CONFIRMED/EXPIRED/INVALIDATED. Order CREATED→AWAITING_PAYMENT→PAID→CONFIRMED→PICKING→PACKED→SHIPPED→DELIVERED→COMPLETED; canceled states only from allowed prior statuses. Payment CREATED→PENDING→SUCCEEDED or FAILED/EXPIRED; refunds separate state machine. RMA REQUESTED→UNDER_REVIEW→APPROVED→AWAITING_RETURN→IN_TRANSIT→INSPECTED→REFUND_PENDING→REFUNDED→CLOSED; alternatives REJECTED/DISPUTED.
For each transition implement transition permission, guard, atomic data mutation, outbox event, audit, notification and compensating action. Invalid transitions return 409 INVALID_STATE_TRANSITION; silent rewrites prohibited.

31. TO‘LIQ TZ: API CONTRACT BEHAVIOR
All /v1 REST calls use standardized JSON {data,meta:{request_id}} and error {error:{code,message,details},request_id}; provider webhooks strictly use provider-native contract. Lists cursor/limit<=100, filter/sort allowlist and explicit permissions. POST /v1/auth/otp/request body {phone,purpose} returns generic 202; POST /v1/auth/otp/verify body {challenge_id,code} returns session/tokens. POST /v1/seller-applications {legal_type,tax_id,legal_name,contacts}→201 DRAFT; /submit requires docs. POST /v1/seller/offers {variant_id,seller_sku,price_minor,currency,fulfillment_mode}→201. GET /v1/catalog/products/{id} includes variants and public offers. POST /v1/checkout/quote {cart_id,address_id,promo_code?} returns quote id/version/expiry, groups, shipping options, computed totals. POST /v1/checkout/confirm {checkout_session_id,quote_version,address_id,payment_provider,delivery_selection} and Idempotency-Key creates one master order, suborders and payment intent. GET /v1/orders/{id} returns own snapshots and shipments. POST /v1/orders/{id}/returns {items:[{order_item_id,quantity,reason}],evidence_keys} returns RMA. 409 stale quote requires reapproval; 422 out of stock includes available quantity. Swagger/OpenAPI full schema must be generated during implementation, and each endpoint has allow/deny contract tests.


32. TO‘LIQ TZ: PAYMENT / LEDGER EXCEPTIONS
Duplicate callback must produce one payment result and one ledger posting. Provider signature/auth, amount, merchant, currency, order and transaction ID must match. Browser redirect alone cannot confirm payment. Out-of-order callback and delayed reversal trigger status reconciliation instead of blind transitions. If payment succeeds after reservation expiry: safe reacquire if stock exists, otherwise hold fulfillment and manual/refund workflow; never oversell. On provider downtime pending payment and retry status check with backoff; do not issue second capture automatically.
Ledger posted transaction balanced debit=credit, immutable; seller pending/available/held balance tracked, commission snapshot per order item. Partial return maximum refunded amount <= originally captured minus previous refunds; rounding allocation deterministic. Daily reconciliation compares provider vs internal transaction with MATCHED/PROVIDER_ONLY/INTERNAL_ONLY/AMOUNT_MISMATCH/STATUS_MISMATCH; auditable corrections. Payout requires approval, only CONFIRMED after actual bank acknowledgment. Contract must determine who collects payment and how sellers receive it.


33. TO‘LIQ TZ: FULFILLMENT SOP
Seller creates ASN inbound to chosen center with offer/variant/expected quantity, packing list and arrival appointment. Warehouse receiving scans and records actual quantity/variance with actor. QC records accepted, rejected, quarantine and evidence. Putaway locates stock using center→zone→aisle→rack→shelf→bin, barcode uniqueness by center, capacity rule. For regulated perishable goods FEFO by expiry; for serial goods serial uniqueness. Picking generates task claim (atomic), expected bin/SKU/lot/qty; wrong scan rejected; shortage handled by exception without faking stock. Packing records carton, weight, dimensions, manifest; dispatch only after pack complete and handover confirmation. Return inbound separately QC inspected before restocking. All stock remains attributed to seller owner even in shared bins. Daily cycle counts with discrepancy approval and stock ledger movement.
Acceptance: expected 100 received 98 produces discrepancy 2; quarantined stock unsellable; one picker wins simultaneous claim; pick > reserved rejected; seller A stock not substituted for seller B order; expiry blocks shipment; missing delivery proof prevents DELIVERED.
