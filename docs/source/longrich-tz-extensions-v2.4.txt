SCOPE: Extension to 36-section Master TZ. Existing core remains source of truth. This tab defines functionality, UI flows, statuses, RBAC, data, APIs, exceptions and acceptance; API names are proposed contracts subject to OpenAPI validation.


APPROVED DEFAULTS: Verified purchase reviews only; review submission delivered_at+90 days; price history append-only subject to retention policy; public prices + privacy-safe aggregated statistics; Longrich-owned + partner PVZs, pickup hold 5 days (120 hours); automated repricing within ±10% cumulative 24h anchored baseline; B2B wholesale price tiers + custom RFQ, quote 7 days (168 hours).


OPEN DECISIONS (DO NOT INVENT): PVZ closed periods extension/reroute rule; published reviews after return; B2B quote renegotiation expiry reset; paid ads pricing contract, referral monetary treatment, historical archival retention exception; pricing anchor changes due manual updates; partner settlements legal model.


GLOBAL RULES: Multi-tenancy and least privilege. No product duplicate canonical cards; never bypass reservation idempotency. Every write audit actor/time/before/after. Provider-native callbacks. Price/bonus/ad events connect to finance ledger, never arbitrary balance writes. All 22 features behind scoped feature flags (GLOBAL, CATEGORY, SELLER, REGION, PVZ as applicable). Cross-seller confidential analytics prohibited.


ROLE AND PERMISSION MATRIX: Buyer owns compare/alerts/reviews/questions/visual search. Verified purchase order item required for reviews. Seller owner/authorized manager imports/catalog integration/repricing/ads/bundles; seller operator scoped inventory only. PVZ partner owner manages own location data; operator scans own parcels; warehouse QC handles return disposition. Moderator reviews public content, admin controls policy, Finance manager handles monetary approvals with maker-checker, B2B buyer authorized company member accepts quotes. No actor gets all operations solely because frontend exposes them.


ACCEPTANCE FRAMEWORK: For each EXT item implement tests: success; invalid input; forbidden cross-tenant; duplicate replay; concurrency if inventory/finance involved; expired/archived state; audit and retry; user-facing feedback, plus responsive/mobile. Link EXT-ID to UI screen, Prisma migration, API OpenAPI operationId, event contract, test ID.


RELEASES: R1 six features; R2 seven; R3 six; R4 three. Release gates require both existing Master TZ G0–G9 dependencies and extension test evidence.
